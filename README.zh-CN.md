# APK 安装管家（macOS）

**[English](README.md) · [日本語](README.ja.md) · [中文](README.zh-CN.md)**

一个 macOS 小工具：把一堆 APK **按你排好的顺序**装进安卓设备。拖进去、排好序、点安装；
换一台手机插上再点一次，还是这个顺序。也能把设备上已装的应用按**你在手机上看到的真实名称**
列出来，点一下就把 APK 提取出来。

纯 Python 标准库 + 本地网页界面，外面包了一层 `.app`。不用 `pip install`，不用 Node，不用 Xcode。
唯一的外部依赖是 `adb`，而且可以在界面里一键下载。

## 功能

**安装队列**
- 把 APK（或整个文件夹）拖进窗口。支持 `.apk` / `.xapk` / `.apks` / `.apkm`，分包会自动用
  `install-multiple` 一起装。
- 拖动调整顺序，也能按应用名 / 文件名 / 包名 / 大小 / 版本号 / 添加时间一键排序。
- **按顺序安装**：一个装完再装下一个，进度实时显示。
- **当前完成后暂停**：正在装的这一个装完就停，不会中途打断；**继续安装**只装剩下的。往一台已经装过一部分的
  设备上再装时，会先问「只装剩下的 / 全部重装」，不会盲目从头来。
- 每次安装任务**绑定一台设备**（连接标识 + 核验过的物理序号）。拔线 → 队列暂停；换插另一台手机也不会自己继续；
  不会改走同一台手机的 Wi-Fi 入口，更不会装到别的设备上。
- 成功要**在设备上核验**：日志出现 `Success` 之后，先确认还是同一台设备，再用 `pm path` + `dumpsys` 读回包信息；
  版本对不上或包不存在标为「未核验」。设备查询失败（包括 Package Manager 自己报错）、或无法确认设备身份时保持
  **「待核验」**，并保留与安装时那台设备的绑定：绝不把查询失败当成「未安装」，换回原机后先核验，不会重复安装。
- 完全无法确认目标身份时（既读不到序号，也没有可靠的连接绑定，比如不提供序号的 Wi-Fi 设备），装完一项就停下，
  之后每一项都要点「继续安装」。因为同一个地址背后可能已经换了另一台手机。
- 把顺序存成命名方案（比如「新机标配」），下一台设备直接载入。
- 每个结果都讲清楚：成功显示版本与用时；失败给出真实原因**和**怎么办（签名冲突 → 先卸载；
  设备版本更高 → 勾选允许降级；手机拒绝 → 允许「USB 安装」等等）。

**已安装标记**
- 接上设备后自动比对队列：*同版本* / *旧版可更新* / *设备版本更高* / *未安装*。
- 一键「只装未安装/可更新」，批量铺机时很省事。

**设备应用 / 提取**
- 列出已装应用的**真实显示名称**（中文应用显示中文）、图标、版本和大小。
- 点**提取**把 APK 拉到 `提取APP/<应用名>_<包名>_<版本>/`。分包应用会完整拉下
  `base.apk` 和所有 `split_*.apk`，并附 `info.txt`。
- 支持单个或批量卸载，可选保留应用数据（`-k`）。

**无线连接（Wi-Fi 调试）**
- 用安卓「无线调试」界面的 6 位配对码配对，或直接连已知的 `IP:端口`。
- 一个按钮把插线的手机转成无线（`adb tcpip` + 自动读取 IP）。
- 设备会标注 **USB** 或 **无线**；同一台手机两种方式都连着时会提示——大安装包走数据线快得多。
- 启动时自动重连上次用过的无线设备；掉线后最多重连 3 次（5 秒 / 15 秒 / 45 秒），之后停下等你手动处理。
- 断开连接只针对你选中的那一个 `IP:端口`，没有「断开全部」。

**ADB 控制台**
- 一个地方看清本程序在对设备做什么：adb 路径、版本、服务端口、能看到的 adb 进程（分为*本程序*／*共享服务*／
  *外部·未知*；服务在运行、5037 端口有进程，本身都不会被报成冲突）。
- 设备连接按**核验过的物理序号**合并，同一台手机的 USB 和 Wi-Fi 两个入口显示为一台；已授权、未授权、离线分开显示。
- 每个后台任务（设备发现、状态查询、无线自动连接、断线重连）的状态（运行中／空闲／已暂停／正在收尾／失败等待）、
  上次成功时间、下次执行时间。
- 安装任务、最近一次失败、此刻正在执行的 adb 命令，以及原始命令记录。
- 控制：**检测一次**、**暂停后台并等待／恢复后台**、**暂停无线后台**、**仅 USB**（只往这台 USB 设备装；不对它做无线扫描、
  重连或 `tcpip`；USB 断开则队列暂停）。

**「暂停后台并等待」**的意思是本程序停止碰设备：正在装的 APK 允许装完，但装完后不再查询（标为「待核验」，
adb 的退出码和输出都保留），也不开始下一项。**「恢复后台」**会先核验待核验项，不会自己继续安装；也不会因为结果
未知就重复安装。**「取消当前」**只向本程序自己的 `adb install` 进程（按 PID）发信号，然后读一次设备；读不到时显示
「结果未知」，而不是「已取消、未安装」。暂停操作一返回，队列和核验都不会再启动新的 adb 命令；暂停之后才返回的
结果也不会写入。

所有自动的 adb 动作都在后端的**同一个调度线程**里执行：刷新页面、开第二个窗口、连点「恢复」，都不会多出一份循环。
暂停状态由后端保存，刷新页面不会自己恢复。程序从不执行 `adb kill-server`，也不会结束不是它自己启动的进程。

**三种语言** —— 中文、日本語、English。右上角切换，macOS 通知文案也跟着变。

## 安装

1. 从 [Releases](../../releases) 下载 `APK-Manager-mac.zip` 并解压。
2. 把 **APK Manager.app** 放到任意位置（应用程序文件夹也行）。
3. **第一次打开需要右键 →「打开」→「打开」**：未签名应用直接双击会被 macOS 拦。想彻底跳过检查：
   ```bash
   xattr -dr com.apple.quarantine "/Applications/APK Manager.app"
   ```
4. 关掉窗口就会退出（约 25 秒后；安装进行中不会退出）。

需要 **Python 3.8 或更新版本**。macOS 本身**并不自带可用的 Python**：在装 Xcode 命令行工具
（`xcode-select --install`，目前会装上 3.9）之前，`/usr/bin/python3` 只是一个空壳入口。也可以用 Homebrew
（`brew install python`）或 python.org 的安装包。启动器按绝对路径依次查找这些位置（从 Finder 启动的程序拿不到
终端里的 `PATH`），都找不到时弹出提示。目前**尚未在真实 Mac 上验证**，请参考[验收清单](docs/MAC_ACCEPTANCE.md)
和 `tools/mac_diagnose.sh`（只读诊断脚本）。

同一时间只运行一份（由锁文件决定；再次双击只会重新打开窗口）。只有旧版本明确报告「空闲」时，才会请它退出、由新版
接管。它正在工作（安装、读取应用列表、提取 APK），或者是 1.5.2 之前、报告不了提取状态的版本时，都不关它；在 macOS 上
会弹提示请你自己退出旧版。关窗口和点「退出」时，这些工作进行中也都会等待。

### 手机设置（只需一次）

1. 设置 → 关于手机 → 连点 7 次**版本号**。
2. 设置 → 开发者选项 → 打开 **USB 调试**（小米等还要打开 **USB 安装**）。
3. 连上数据线，在手机上点**允许**。

Mac 上没有 `adb`？进**设置 → 自动下载 adb**，程序会从 Google 官方源取 platform-tools。

## 实现说明

| 文件 | 作用 |
| --- | --- |
| `core/binxml.py` | 安卓二进制 XML 与 `resources.arsc` 解析器，自己写的，不依赖 `aapt` |
| `core/apkinfo.py` | 包名、版本、**真实本地化应用名**、图标；支持 `.xapk`/`.apks` 捆绑包 |
| `core/adbkit.py` | adb 封装：设备、安装、配对/连接，以及远端 APK 的局部读取 |
| `core/supervisor.py` | 所有自动 adb 任务唯一的调度入口：暂停／恢复、仅 USB、有限次重试 |
| `core/engine.py` | 队列、顺序方案、安装流程（设备绑定、暂停边界、结果核验）、已装标记、卸载、提取 |
| `core/server.py` | 本地 HTTP + SSE 服务，只监听 `127.0.0.1` |
| `web/` | 界面（原生 JavaScript，无框架）与多语言文案表 |

有几点值得一提：

**不整包拉取也能读到真实应用名。** 直接从设备读标签意味着可能要拷几十 GB。这里的做法是：先读远端
APK 的 zip 中央目录，然后只取 `AndroidManifest.xml` 和 `resources.arsc` 两段（通过
`adb exec-out` 的 `tail`/`head`），在本地解析，再按界面语言挑选对应的标签。结果按包名缓存。

**迟到的结果不会覆盖暂停。** 每次暂停都会让代次号加一。暂停时已经在跑的任务显示「正在收尾」，它返回时如果代次号
已经变了，结果直接丢弃——慢吞吞的 `adb devices` 不会把旧数据当成「实时」重新画出来，状态查询也不会落到你已经
换掉的设备上。

**启动路径上没有重活。** 启动器只负责 `exec` 到 Python，不再为了挑端口多起一次解释器。
Python 会在**导入服务端模块之前**先绑好监听套接字并拉起浏览器，让浏览器冷启动和 import 并行进行。
字节码在打包时预编译进 bundle（放在 /Applications 里的 `.app` 写不了 `__pycache__`，否则每次启动都要重编）。
adb 守护进程在后台线程预热，用过的浏览器会记住。程序已在运行时再次打开会复用现有实例，不会起第二个服务。

## 测试

不需要真机：`tests/fakeadb/adb` 是一个假 adb，能模拟拔线、未授权和离线设备、同一个 Wi-Fi 地址背后换成另一台手机、
重连失败、安装中途被打断、安装报 `Success` 但实际没装上等情况。

```bash
sh tests/get_test_apks.sh        # 第一次：下载 3 个开源的真实 APK 到 tests/apks/
python3 tests/acceptance.py      # 全部 22 个场景（约 10 分钟）
python3 tests/acceptance.py 10 13  # 只跑部分场景
APKMGR_TEST_SERVER_PY=/path/to/python3.9 python3 tests/acceptance.py   # 用 3.9 运行程序
APKMGR_TEST_EVIDENCE=./evidence python3 tests/acceptance.py            # 保留 adb 命令记录
python3 tests/delivery_check.py --zip APK-Manager-mac-v1.5.2.zip --py39 /path/to/python3.9
python3 tests/diag_check.py      # 确认诊断脚本对 adb 只执行 `adb version`
APKMGR_TEST_CODE=/path/to/old/checkout python3 tests/acceptance.py 17   # 用同一套测试跑旧代码
```

`acceptance.py` 覆盖：USB 安装时暂停无线后台、重连失败时暂停等待、不管开几个窗口或连点几次「恢复」都只有一个调度
线程、同一台手机 USB／Wi-Fi 同时接入、安装中拔线、未授权／离线／连接失败／暂停的区分、不干扰其他使用 adb 的程序、
在设备上核验安装结果、安装队列的暂停边界、安装中暂停后台（待核验、不重复安装）、迟到结果在写入前被拦截、核验绑定
同一台设备、取消只结束本程序的进程、并发启动和旧版升级下只有一个实例、暂停期间无 adb 通信、「检测一次」只执行一次；以及 v1.5.2 新增的：身份查询中 / 核验中暂停、换机后待核验不丢、Package Manager 报错、
身份无法确认的目标、提取也算忙碌。并发时序用假 adb 的「屏障」固定（把命令卡在指定位置，等测试放行），
不靠反复运行或 sleep。
`delivery_check.py` 把发布 ZIP 解压到带中文和空格的路径，用接近 Finder 的最小环境、只读的程序包、Python 3.9、
安装中强制退出、以及 v1.4／v1.5.0 的旧数据分别启动检查。

## 隐私

全部在你自己的 Mac 上运行，只监听 `127.0.0.1`，不上传任何东西。唯一的外部请求是从 Google 下载
platform-tools，而且只在你点那个按钮时才会发生。

数据放在 `~/Library/Application Support/APK安装管家/`（队列、顺序方案、设置、图标缓存），日志在
`~/Library/Logs/`。删掉 app 和这两个目录就卸载干净了。

## 常见问题

**一直显示「未检测到设备」。** 数据线要能传数据（充电线不行），换个 USB 口，确认手机上点过允许，
再点「刷新设备」。

**安装卡住不动。** 多半是手机上弹了确认框，解锁看一眼。部分机型需要在开发者选项里打开「USB 安装」。

**读取应用列表很慢。** 第一次要读每个应用的信息，几百个应用大概几分钟，之后有缓存。选「用户安装的
应用」比「全部」快得多。

**暂停了无线后台，却还是出现了无线连接。** 暂停只保证「本程序」不再发起连接。其他程序可能会连接设备，adb 服务
本身也可能自动连接以前配对过的设备。控制台能判断连接是不是本程序发起的；不是的话就写「不是本程序发起的连接
（来源无法确定）」，不再往下猜。程序不会替你重启共享的 adb 服务或修改它的设置。

**有的应用卸载不掉。** 预装系统应用没法用这种方式删除，程序会直接告诉你是这个原因。
